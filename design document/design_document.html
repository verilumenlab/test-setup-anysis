How the STIL Setup Optimizer Works

A clean, straightforward mechanism: we add the STIL files, analyze their test setups clock-by-clock, apply deterministic DFT rules, run the Learning-to-Defer model, and display a review report recommending each clock as Keep or Redundant.

The 5 Mechanism Steps Explained Walkthrough

Step 1 & 2: Add STIL Files & Analyze Test Setup

The engineer loads STIL files into the tool (such as Stuck-At, ScanShift, or MBIST files for different chip partitions).

  • Extracts Setup: The parser isolates the TEST_SETUP bring-up and stops where the real scan test patterns start.
  • Unrolls Clocks: Expand loops (e.g. Loop 5 becomes 5 individual tester clocks) so every clock cycle can be inspected.
  • Genuine Commonality: Lines up files clock-by-clock and measures how much of the setup is identical across files.

Step 3: Apply Deterministic DFT Rules

Known DFT & JTAG rules check for obvious wasted cycles that do zero hardware work:

  • Duplicate Reset Hold: Identical reset pin levels to the clock before (the chip is already in reset; no new edge is made).
  • Second TAP Reset: A 5-clock TMS=1 reset when TRST already put the TAP in Test-Logic-Reset.
  • Extra Idle: Static TCK=0 holds after reset is already released or after Update-DR already latched data.
  • Protected Clocks: SIB partition bits, TDR config bits, and Shift-IR instructions are permanently protected and cannot be cut.

Step 4: Learning-to-Defer (LtD) Model

A machine learning model (Gradient Boosting) works alongside the rules to evaluate each clock:

  • Confidence Score: Calculates probability $P(\text{cut})$ that an experienced test engineer would approve removing the clock.
  • Automatic Recommendation: High probability → Recommend Redundant; Low probability → Recommend Keep.
  • Learning-to-Defer: Borderline cases ($0.35$ to $0.65$) are marked Defer, asking the engineer to make the final call.
  • Learns from Engineer: When you click Keep or Reject, the model saves the decision and retrains so it gets smarter over time.

Step 5: Shows Report & Recommends Keep / Redundant

The dashboard displays an easy-to-read report showing every setup clock, the applied rule, and the model recommendation:

  • Keep: Clocks required to initialize the chip, open the partition SIB, and configure registers.
  • Redundant: Wasted duplicate holds or extra idle clocks recommended for deletion.
  • Zero Risk: Nothing is deleted until the engineer approves. Then, it outputs clean *_opt.stil files with untouched test payloads.
